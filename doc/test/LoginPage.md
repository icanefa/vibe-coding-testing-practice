# LoginPage 測試案例清單

> 狀態：初始為 [ ]、完成為 [x]
> 注意：狀態只能在測試通過後由流程更新。

---

## [x] 【前端元素】初始畫面渲染
**範例輸入**：載入 LoginPage 頁面  
**期待輸出**：應該正確渲染 Email 輸入框、密碼輸入框以及「登入」按鈕

---

## [x] 【輸入驗證】Email格式不正確時顯示錯誤訊息
**範例輸入**：在 Email 欄位輸入「invalid-email」，輸入有效密碼並點擊登入  
**期待輸出**：畫面應顯示「請輸入有效的 Email 格式」錯誤訊息，且不呼叫登入 API

---

## [x] 【輸入驗證】密碼長度不足8碼時顯示錯誤訊息
**範例輸入**：在 Email 欄位輸入「test@example.com」，密碼欄位輸入「abc1234」(7碼) 並點擊登入  
**期待輸出**：畫面應顯示「密碼必須至少 8 個字元」錯誤訊息，且不呼叫登入 API

---

## [x] 【輸入驗證】密碼缺乏英文字母或數字時顯示錯誤訊息
**範例輸入**：在 Email 欄位輸入「test@example.com」，密碼欄位輸入「12345678」(無英文) 或「abcdefgh」(無數字) 並點擊登入  
**期待輸出**：畫面應顯示「密碼必須包含英文字母和數字」錯誤訊息，且不呼叫登入 API

---

## [x] 【邏輯流程】表單驗證失敗時，不應呼叫 login API
**範例輸入**：輸入錯誤的 Email 格式與不合規定的密碼並點擊登入  
**期待輸出**：顯示對應的欄位錯誤訊息，不進入 Loading 狀態，不呼叫 login API

---

## [x] 【邏輯流程】登入中狀態顯示
**範例輸入**：填寫正確的 Email 與密碼並點擊登入，模擬 API 延遲回應  
**期待輸出**：登入按鈕應顯示「登入中...」及 loading spinner，且按鈕與所有輸入框皆變為 disabled 狀態

---

## [x] 【Mock API】登入成功後導航至 Dashboard
**範例輸入**：輸入正確格式的 Email 與密碼，Mock login API 回傳成功  
**期待輸出**：API 呼叫結束後，應使用 navigate 導航至 `/dashboard`（使用 replace: true）

---

## [x] 【Mock API】登入失敗時顯示 API 錯誤訊息
**範例輸入**：輸入錯誤的帳號密碼，Mock login API 回傳 Axios 錯誤 (包含 `{ message: '登入失敗，請稍後再試' }`)  
**期待輸出**：畫面上方的錯誤區塊 (`role="alert"`) 應正確渲染並顯示對應的錯誤訊息

---

## [x] 【狀態處理】已登入用戶直接導航
**範例輸入**：設定 AuthContext 的 `isAuthenticated` 為 `true`  
**期待輸出**：元件載入後應不需登入操作，直接導航至 `/dashboard`（使用 replace: true）

---

## [x] 【狀態處理】處理憑證過期訊息
**範例輸入**：設定 AuthContext 的 `authExpiredMessage` 為「登入已過期」  
**期待輸出**：畫面應顯示「登入已過期」錯誤訊息，且應呼叫 `clearAuthExpiredMessage()` 函式清空該訊息
